# JUICY Academy — полное техническое задание
Owner-approved MVP scope, редакция 2026-11-06.

Owner override 2026-11-08: Mux Basic 1080p replaces the prior video provider. Direct browser uploads, verified webhooks, signed private playback and duration-aware renewal; DRM disabled. See MUX_SETUP.md.

## 1. Бизнес-цель и критерий успеха

Создать доступную в браузере закрытую академию кулинарии Назерке для покупателей Kenwood с промокодом JUICY. Дать им уроки, видео, рецепты, насадки, курсы, анонсы и поддержку. Назерке должна самостоятельно управлять публикациями и доступом через понятную админку.

Успешный MVP: подтверждённый пользователь входит через Telegram, смотрит только разрешённые материалы, прогресс и избранное реально сохраняются на сервере, закрытое видео выдаётся по защищённому просмотру; уполномоченный админ может без разработчика создать/опубликовать рецепт, урок, курс; пользователь получает поддержку. Первый релиз — закрытый пилот, затем улучшения.

НЕ включать: продажи/оплату/рассрочку/корзину, CRM, маркетплейс, подписки, сертификаты, сложное тестирование, мобильные приложения, выплаты амбассадорам, маркетинговые воронки.

## 2. Одна платформа, три интерфейса

**Public JUICY by Nazerke**: Главная /, Об академии /about, открытые Статьи /articles и /articles/[slug], публичные Мастер-классы /events, Контакты /contacts, Войти, privacy/terms. Ровно один публичный хедер. Главная: hero с Назерке, краткое объяснение JUICY, 4 направления, 3 открытые статьи, о Назерке, только реальные события, как получить доступ, контакты. На открытых статьях нет закрытого видео.

**Closed JUICY Academy**: /academy, /academy/learn, /academy/kenwood, /academy/lessons/[slug], /academy/attachments, /academy/courses/[slug], /academy/recipes, /academy/recipes/[slug], /academy/collections/[slug], /academy/events, /academy/materials, /academy/club, /academy/ambassadors, /academy/profile. Ровно один внутренний хедер, без публичного поверх него. Desktop навигация: Главная, Обучение, Рецепты, Мастер-классы, Материалы, JUICY Club + поиск и ОДИН аватар/профиль. Mobile снизу: Главная, Обучение, Рецепты, Встречи, Ещё; сверху поиск и профиль. Персональный dashboard: приветствие с фото, либо «Начните здесь» (нет прогресса), либо «Продолжить» (есть прогресс), направления, новые рецепты, реальные мероприятия и объявления. Никакого второго «Личного кабинета» плиткой.

**Admin JUICY Studio**: /admin и отдельные страницы управления контентом, курсами, рецептами, разделами, медиа, пользователями, обращениями, анонсами, ролями и аудитом. Ученик/амбассадор не видит ссылок на Studio даже в мобильной навигации и не может открыть защищённые API напрямую. Обычный админ видит только выданные права. Тех. админ может назначать админов и их grants. Раздел /preview разрешён только для демонстрации в DEV; клиент не может переключить себе роль.

## 3. Обучение и каталог

**Kenwood с нуля:** 10 последовательных уроков: знакомство, комплектация, первый запуск, экран, весы/температура/таймер, базовые насадки, встроенные рецепты, первая готовка, уход, FAQ. У каждого урока заголовок, описание, видео/контент, вложения и отметка прогресса.

**Насадки:** Food Processor, кубикорезка KAX400PL, тестораскатка KAX980ME, лапшерезка KAX982ME, мясорубка KAX950ME, соковыжималка KAX720PL, блендер и прочие по факту. У каждой: фото именно оборудования, модель, назначение, сборка, применение, уход, типичные ошибки и связанные рецепты.

**Курсы JUICY:** «Заготовки и полуфабрикаты», «Кондитер с нуля», «Десерты с нуля», «Тесто, хлеб и выпечка». Структура курс → упорядоченные модули → упорядоченные уроки. Сохранять прогресс и порядок независимо от удаления ссылок.

**Рецепты:** фото конкретного готового блюда; название, категория, описание, время, порции, ингредиенты/количество, пошаговая технология, параметры Kenwood (когда применимо), насадки, видео, PDF. Поиск и фильтры: категория, насадка, время, язык RU/KZ. Избранное/прогресс на сервере.

**Кухни мира / тематические столы:** коллекции (Италия, казахский дастархан, Восток, Наурыз, ифтар, Новый год, завтрак и т.д. по мере реальных материалов). Каждая: вводная, рецепты по ссылке, общий список закупок и подготовительный план. **Один рецепт/одно медиа используется многократно** через отношения; не копировать видео или рецепт для каждой подборки.

**Сбалансированное питание** скрыто до заполнения. Не делать пустых категорий на витрине.

**Мастер-классы:** актуальные офлайн-анонсы по городу и дате, заявка/лист ожидания/интерес к городу; записи прошедших и связанные материалы. Никаких вымышленных мероприятий, времени, городов или регистраций.

**Материалы:** статьи, книги, памятки, чек-листы, PDF и скачиваемые материалы с серверной проверкой допусков.

**JUICY Club:** FAQ, новости, клиентские предложения, поддержка и запросы тем. Предложения — информационные, без покупки на сайте.

**Школа амбассадоров:** отдельный учебный допуск. Программа продуктовая экспертиза, демонстрации техники, личный бренд/контент, работа с клиентами, практика и наставничество. Ученик видит описание без закрытых уроков. Само прохождение не даёт административных прав.

## 4. CMS в admin

Админ с соответствующими grants создаёт/редактирует разделы, рецепты, уроки, модули, курсы, коллекции, FAQ, посты, анонсы; назначает связанные медиа; меняет порядок. Кнопки «Черновик», «Предпросмотр», «Опубликовать», «Скрыть», «Архивировать». Публикация/удаление отделены от права редактирования. Загрузка фото/файлов/видео через защищённый серверный поток, без секретов в браузере. Все изменения реально сохраняются в PostgreSQL и видны после повторного входа. Статический localStorage demo не засчитывается. Действия над контентом и доступами логируются.

## 5. Вход и подтверждение

Telegram login на официальной поддерживаемой схеме. Backend проверяет цифровую подпись/hash, срок auth_date, origin и bot identity по документации интеграции. Нельзя верить Telegram ID, role, status или access на основе клиентского JS без server verification. Новый пользователь pending до подтверждения. Только approved пользователь с действующей сессией и назначенным учебным entitlement читает закрытые API/видео.

Telegram bot webhook получает update с проверяемым secret, idempotency по update_id, безопасным редактированием данных, rate limiting. Вебхуки исполняются через Vercel Functions, без Railway.

## 6. Одно устройство / сессия

Один зарегистрированный **браузер** на одного ученика и одна активная серверная сессия. Secure + HttpOnly + SameSite cookie; непрогнозируемый session token хранить только в виде хеша; сервер проверяет каждое обращение. Атомарная операция в PostgreSQL для первых одновременных входов: только один браузер получает binding. Второму показывать корректный отказ/восстановление доступа. Несколько вкладок одного браузера допустимы. Сброс привязки — только админ с devices.reset или тех. админом, с аудитом. Cookie удалён → новый binding не разрешать автоматически. Нельзя выдавать устройство за неуязвимую аппаратную идентификацию.

## 7. Роли, права и ограничения

Пять бизнес-ролей: guest (открытый), student (одобренное обучение), ambassador (student + амбассадорский курс), admin (настраиваемые точечные права), techadmin (управление админами, правами, платформой). Тех. админ назначает, изменяет, отзывает admin-grants. Админ не может назначать других админов, редактировать свои права или повышать себя в techadmin. Backend проверяет каждую операцию, не только прячет кнопку. Админские права не означают доступ ко всем частным данным учеников. Профили, прогресс и обращения — ownership checks, server-side deny 401/403 для чужих данных. Лог изменений с минимумом PII.

## 8. Медиа и документы

Mux для закрытых видео. После проверки user/session/content entitlement сервер генерирует signed playback token/URL с длительностью урока и безопасным обновлением. Нет публичной постоянной ссылки в markup, API, клиентских исходниках и логах. Обработать processing/upload-failed/expired. Прямой запрет записи экрана не обещаем. Документы выдавать через подписанную ссылку после проверки доступа. Изображения витрины могут быть публичными; авторские фото и контент не генерировать автоматически.

## 10. Технологии / non-functional

Next.js App Router с TypeScript на Vercel, серверные Route Handlers/Server Actions. PostgreSQL Neon с миграциями, атомарными транзакциями и indexes; Mux; Telegram. Минимум внешних сервисов и отсутствие постоянного сервера. Раздельные DEV и PROD базы/секреты. Защита от XSS/CSRF, IDOR, replay, privilege escalation; лимиты на загрузку и rate limiting. Логи без секретов, резервное копирование и тест восстановления до реальных пользователей. Уточнить требования Казахстана к персональным данным до пилота; не использовать реальные клиентские данные в DEV. Адаптивность mobile-first, понятные error/loading/empty states, доступность клавиатуры и контраст.

## 11. Результат и приёмка

Пилот готов, когда реальный Telegram login + ручное одобрение, backend-RBAC, 1 device/session, CMS, приватное видео, прогресс, избранное, поиск и поддержка доказательно работают с тестовыми аккаунтами в DEV и smoke в PROD. Детальные негативные и функциональные тесты — QA.md. Факт Vercel READY и 44/44 теста старого демо не заменяют backend тестов.

## 12. Процесс

Только DEV → PROD. Codex вносит code, запускает тесты в DEV, фиксирует SHA и PR, затем после корректного release decision деплоит в PROD и проверяет smoke/rollback. Нет TEST tier. Решения по инженерной реализации делаются самостоятельно; не раздувать scope, не просить Owner на каждую мелочь. Ошибки исправлять по мере появления, двигаться короткими вертикальными срезами.
